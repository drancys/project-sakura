# 第6節　JSONファイルへ保存する

次にPythonのデータをJSONファイルに保存します。

```python
import json

articles = [
    {
        "id": 1,
        "title": "Project Sakura 第9章",
        "category": "Python",
        "status": "draft",
        "url": ""
    },
    {
        "id": 2,
        "title": "Project Sakuraについて",
        "category": "Project Sakura",
        "status": "published",
        "url": ""
    }
]

with open("articles.json", "w", encoding="utf-8") as file:
    json.dump(articles, file, ensure_ascii=False, indent=2)

print("記事データを保存しました。")
```

このプログラムを実行すると、

```text
articles.json
```

が作成されます。

# 第7節　JSONからデータを読み込む

今度は逆です。

保存したJSONファイルをPythonで読み込みます。

```python
import json

with open("articles.json", "r", encoding="utf-8") as file:
    articles = json.load(file)

for article in articles:
    print(article["title"])
```

実行すると、登録されている記事タイトルが表示されます。

```text
Project Sakura 第9章
Project Sakuraについて
```

これで、

**保存 → 読み込み**

という基本的な流れが完成しました。

## 9.2　articles.jsonによる記事情報の管理

Project Sakuraでは、記事に関する情報を `articles.json` で管理します。

記事には、本文だけではなく、記事を管理するために必要なさまざまな情報があります。

例えば、次のような情報です。

- 記事ID
- 記事タイトル
- カテゴリ
- 公開状態
- URL
- 本文ファイル

これらの情報を一つのデータとしてまとめて管理することで、Pythonから記事を検索したり、編集したり、削除したりできるようになります。

`articles.json` は、いわばProject Sakuraの記事情報を管理するための台帳です。

例えば、記事情報は次のような形で管理します。

```json
{
    "id": 1,
    "title": "記事タイトル",
    "category": "テスト",
    "status": "draft",
    "url": "",
    "content_file": "articles/article_001.md"
}

ここで重要なのは、articles.json に記事本文そのものをすべて保存するのではなく、記事を管理するための情報を保存するという考え方です。

記事本文については、別のMarkdownファイルとして管理します。

このように、

articles.json → 記事の管理情報
articles/article_001.md → 記事本文

という役割分担をすることで、データを整理しやすくなります。

この構造は、今後の記事数が増えた場合にも重要になります。

記事が10件、100件、1000件と増えていった場合でも、記事情報を一定の形式で管理しておけば、Pythonによる検索や編集などの処理を自動化できます。

## 9.3　Markdownによる記事本文の分離

記事の管理情報を `articles.json` にまとめる一方で、記事本文は別のMarkdownファイルとして管理します。

例えば、記事IDが1の場合、本文ファイルは `articles/article_001.md` となります。

記事IDが8の場合は、`articles/article_008.md` となります。

このように、記事本文をそれぞれ独立したMarkdownファイルとして保存することで、記事の管理情報と本文を分離できます。

`articles.json` には記事のタイトルやカテゴリ、公開状態などの管理情報を保存し、実際の記事本文はMarkdownファイルに保存します。

この構造には、いくつかのメリットがあります。

- 記事情報と本文を分けて管理できる
- Markdownを使って本文を編集できる
- 記事本文だけを個別に読み込める
- Pythonから本文を保存・更新できる
- 将来的にHTMLやWordPressなどへ変換しやすくなる

特にProject Sakuraでは、記事本文をMarkdownで管理することが重要です。

Markdownは人間が直接読んで編集しやすく、見出しや箇条書きなどの構造も表現できます。

そのため、Pythonで記事データを管理しながら、本文についてはMarkdownの書きやすさをそのまま利用できます。

つまり、Project Sakuraでは、

- `articles.json` → 記事を管理するためのデータ
- `articles/article_001.md` → 実際の記事本文

という役割分担を基本とします。

この分離によって、記事数が増えてもデータを整理しやすい構造になります。

## 9.4　記事IDと本文ファイルの紐付け

記事情報と記事本文を別々に管理する場合、それぞれのデータがどの記事のものなのかを識別できる仕組みが必要になります。

Project Sakuraでは、記事IDを使って記事情報と本文ファイルを紐付けます。

例えば、記事IDが1の場合、本文ファイルは `articles/article_001.md` です。

記事IDが8の場合は、本文ファイルは `articles/article_008.md` です。

このように、記事IDを3桁の数字としてファイル名に含めることで、記事と本文ファイルの対応関係を分かりやすくしています。

さらに、`articles.json` の `content_file` に本文ファイルの場所を保存します。

例えば、記事IDが8の場合は、次のようになります。

- `id` → 8
- `content_file` → `articles/article_008.md`

Pythonプログラムは、この `content_file` の情報を利用して、該当するMarkdownファイルを読み込んだり、保存したりします。

記事を新しく追加するときには、記事IDから本文ファイル名を自動的に作成します。

これにより、記事を追加するたびに本文ファイルの名前を手作業で決める必要がなくなります。

記事IDと本文ファイルを一定の規則で紐付けておくことは、記事数が増えたときにも重要です。

同じルールで管理することで、Pythonから目的の記事本文を正確に取得できるようになります。

この仕組みが、Project Sakuraの記事データ管理の基本になります。

## 9.5　記事本文の読み込み

記事本文をMarkdownファイルとして分離した場合、Pythonプログラムからその本文を読み込む必要があります。

Project Sakuraでは、記事本文を読み込むための関数を用意します。

関数名は `load_article_content()` とします。

この関数では、指定されたMarkdownファイルを開き、保存されている本文を読み込みます。

ファイルを読み込むときには、読み込みモードの `r` とUTF-8を指定します。

読み込んだ本文は、Pythonの文字列として扱うことができます。

これによって、Pythonプログラムから記事本文を表示したり、内容を確認したりできるようになります。

例えば、記事ID 8の記事であれば、`articles/article_008.md` を読み込むことで、その記事の本文を取得できます。

このように、記事情報から本文ファイルの場所を取得し、そのファイルをPythonから読み込むという流れになります。

また、指定された本文ファイルが存在しない場合には、エラーが発生する可能性があります。

そのため、実際のプログラムではファイルが存在しない場合にも処理を止めないよう、例外処理を利用します。

記事本文の読み込み処理を関数としてまとめておくことで、記事本文を表示する処理などから同じ機能を何度も利用できます。

これは、今後Project Sakuraの機能を増やしていくうえでも重要な考え方です。

## 9.6　記事本文の保存

記事本文を読み込めるようになったら、次に必要になるのが本文の保存です。

Project Sakuraでは、記事本文をMarkdownファイルに保存します。

本文を保存するときには、指定されたMarkdownファイルを書き込みモードで開きます。

書き込みモードには `w` を使用し、文字コードにはUTF-8を指定します。

Pythonから本文を書き込むことで、記事本文を手作業でファイルに保存する必要がなくなります。

例えば、記事ID 8の記事本文を編集した場合、編集後の本文を `articles/article_008.md` に保存します。

この保存処理も関数としてまとめます。

関数名は `save_article_content()` とします。

本文を保存する処理を関数として分離することで、記事本文の編集機能などから同じ保存処理を利用できるようになります。

記事本文の編集では、まず現在の本文を読み込みます。

その後、ユーザーが新しい本文を入力し、編集後の内容を保存します。

この流れを整理すると、次のようになります。

1. Markdownファイルから現在の本文を読み込む
2. 本文を編集する
3. 編集後の本文を保存する
4. 次回読み込んだときに、保存した本文が表示される

このように、読み込みと保存をそれぞれ関数として用意することで、記事本文を安全に管理しやすくなります。

また、JSONには記事本文そのものを保存せず、本文ファイルの場所だけを管理します。

これにより、記事情報と記事本文を分離した状態を維持できます。

この仕組みは、今後の記事生成やHTML変換、WordPressへの投稿などへ発展させる際にも利用できます。

## 9.7　記事本文の追加・編集・表示

ここまでで、記事本文をMarkdownファイルとして読み込む方法と保存する方法を整理しました。

次に、これらの機能を記事管理プログラムの中で利用します。

Project Sakuraでは、記事情報の管理と記事本文の管理を組み合わせることで、記事を一つのまとまりとして扱えるようにします。

記事本文に関する主な操作は、次の3つです。

1. 記事本文を追加する
2. 記事本文を編集する
3. 記事本文を表示する

さらに、記事を削除した場合には、対応する本文ファイルも削除します。

### 9.7.1　記事追加時の本文ファイル生成

記事を新しく追加するときには、記事情報だけでなく、対応するMarkdownファイルも自動的に作成します。

例えば、新しい記事のIDが8であれば、本文ファイルとして `articles/article_008.md` を作成します。

作成されたMarkdownファイルには、記事タイトルやカテゴリー、概要、本文、まとめなどの基本的な構成を用意します。

これにより、新しい記事を追加した時点で、記事本文を入力するためのファイルが準備されます。

本文ファイルの名前を手作業で決める必要がないため、記事数が増えても一定のルールで管理できます。

### 9.7.2　記事本文の表示

記事本文を確認するときには、記事情報に保存されている `content_file` を利用します。

Pythonプログラムは、`content_file` に記録されたMarkdownファイルを読み込み、その内容を画面に表示します。

これにより、記事一覧で確認した記事について、必要なときに本文まで確認できるようになります。

本文を読み込む処理には、9.5で整理した `load_article_content()` 関数を利用します。

### 9.7.3　記事本文の編集

記事本文を編集するときには、現在保存されている本文を確認したうえで、新しい本文を入力します。

入力された本文は、9.6で整理した `save_article_content()` 関数を利用してMarkdownファイルへ保存します。

この処理によって、記事本文の変更をJSONではなくMarkdownファイルへ反映できます。

記事情報と記事本文を分離して管理することで、記事の基本情報を変更する処理と、本文を変更する処理を独立して扱うことができます。

### 9.7.4　記事削除時の本文ファイル削除

記事を削除するときには、`articles.json` から記事情報を削除するだけでは不十分です。

対応するMarkdownファイルが残ってしまうと、不要なファイルが増えてしまいます。

そのため、記事削除時には `content_file` に記録されている本文ファイルも削除します。

例えば、記事ID 8を削除する場合には、記事情報を `articles.json` から削除すると同時に、`articles/article_008.md` も削除します。

このように、記事情報と本文ファイルをセットで管理することで、不要なデータが残ることを防ぎます。

記事本文の追加、編集、表示、削除を一連の流れとして管理することで、Pythonによる記事データ管理の基本機能が完成します。

## 9.8　空本文への安全対策

記事本文を編集するときには、入力された本文が空になっていないか確認する必要があります。

本文を空のまま保存してしまうと、以前保存されていた記事本文が失われる可能性があります。

そのため、Project Sakuraでは、記事本文を保存する前に入力内容を確認します。

入力された本文から空白や改行だけの部分を除き、実際に文字が入力されているかを確認します。

本文が空の場合には、保存処理を実行せず、更新を中止します。

一方、本文に文字が含まれている場合には、通常どおりMarkdownファイルへ保存します。

このような確認処理を入れることで、誤操作によって既存の記事本文を空にしてしまうことを防げます。

記事本文を扱うプログラムでは、入力されたデータをそのまま保存するのではなく、保存前に最低限の確認を行うことが重要です。

特に、記事データが増えてくると、一度失った本文を手作業で復元することは難しくなります。

そのため、空本文への対策は小さな処理であっても、記事データを守るための重要な仕組みになります。

この考え方は、今後Project Sakuraで自動生成やWordPressへの投稿機能を追加するときにも役立ちます。

## 9.9　記事管理プログラムの構造整理

ここまで作成してきた機能を整理すると、Project Sakuraの記事管理プログラムは複数の役割に分けて構成されています。

記事本文については、Markdownファイルを利用します。

このように、処理ごとに役割を分けて関数を用意することで、プログラム全体の構造を整理できます。

記事管理プログラムの主な役割を整理すると、次のようになります。

今後の自動記事生成、HTML変換、WordPress投稿などへ発展させるための基礎となるデータ管理システムです。

## 9.10　Chapter 9のまとめ

Chapter 9では、Pythonを利用した記事データ管理の仕組みを整理しました。

Project Sakuraでは、記事の基本情報を `articles.json` に保存し、記事本文をMarkdownファイルとして分離して管理します。

記事を追加するときには、記事IDから本文ファイルを自動生成します。

記事を削除するときには、`articles.json` の記事情報だけでなく、対応するMarkdownファイルも削除します。

さらに、記事本文の編集時には空本文を保存しないようにすることで、誤操作による本文消失を防ぎます。

Chapter 9で作成した仕組みを整理すると、次のようになります。
